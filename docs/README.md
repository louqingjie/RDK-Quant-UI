# 文档

`docs/` 按**用途**分目录。写之前先确定它属于哪一类 —— 放错层的文档要么被挪走，要么没人看。

根 [`AGENTS.md`](../AGENTS.md) 只留一句「先看这里」，方法的主体在这份文件。

## 放哪里

| 目录 | 收什么 | 不收什么 |
|---|---|---|
| `adr/` | 一个**已经定下来、不打算反悔**的决定：问题 / 选择 / 替代方案 / 代价 | 还没定的、还可能改的 |
| `rfcs/` | **还没定**的提案，用来征集意见 | 已决定的（定了就转 `adr/`） |
| `design/` | 系统**当前**长什么样，以及**约束它的实测事实** | 演进过程（那在 `adr/` 和提交信息里） |
| `guides/` | 怎么用、怎么做 —— 面向使用者和贡献者的步骤 | 架构理由 |
| `operations/` | 运维：环境、发布、监控 | 开发流程 |
| `operations/runbooks/` | **照着敲就能修好**的排障步骤 | 原因分析 |
| `postmortems/` | 事故复盘：发生了什么 / 为什么 / 怎么防 | 一般性的坑 |
| `pitfalls/` | 踩过的坑：错在哪 / 为什么会错 / **怎么发现的** | 不是坑的设计说明 |
| `templates/` | 上面各类的模板 | 真正的内容 |
| `assets/` | 图片、示意图 | 文本 |

一句话判断：**我要写的是事实、决定、步骤，还是教训？**

## 命名

全小写、连字符：`pitfalls/qt-traps.md`、`design/container-findings.md`。
`adr/` 和 `rfcs/` 带四位序号：`adr/0007-host-side-thumbnails.md`。

ADR **只增不改**。决定被推翻时新写一份，在 `Supersedes` 里链回旧的 —— 改旧的那份等于抹掉当时的理由。

## 写法

- **一个事实只有一个家。** 别处要用就链接过来。复制一份迟早会漂移。
- **写当前状态。** 历史留在提交信息里；引用历史用提交号，不用「上次改的时候」。
- **说数字，不说形容词。**「快了很多」没用，「169 秒 → 9.26 秒」有用。
- **没验证就标出来。**「测过了」和「应该可以」要能一眼分开。宁可写「未验证」。
- **踩过的坑写清三件事**：错在哪、为什么会错、怎么发现的。只写结论，后人不知道边界在哪。
- **文档和代码冲突时，先假设代码是对的**（它经过实测），去改文档。反过来做，等于把已经修好的问题重新装回去。改完在提交信息里说明哪一处漂移、为什么。

## 篇幅

这个项目没有文档门禁，只有 `pytest`。超了先看是不是放错了层，**先搬家，再压缩，最后才考虑放宽**。

| | 参考上限 |
|---|---|
| `design/` 单篇（叙述型设计） | 150 行 |
| `design/` **集合类参考**（schema、实测清单） | **一节 ≤ 40 行**，总长不限 |
| `adr/`、`postmortems/` 单篇（一件事一篇） | 80 行 |
| `pitfalls/` **单条** | 25 行 —— 多条可以合成一篇（`qt-traps.md` 现在 7 条） |
| `operations/runbooks/` 单篇 | 60 行（照着敲的，长了没人看） |
| `guides/` | 不设行数，但要能一口气读完 |

**集合类文件按「条/节」限，不按「篇」限。** `pitfalls/`、`design/config-yaml.md`、
`design/container-findings.md` 这类是**一条一条攒起来的**；按篇限行数会逼着人
为了加新知识去删旧知识 —— 那是反的。判断标准是**它会不会持续增长**：
会，就按节限；不会（一篇 ADR 讲一个决定），就按篇限。

## 改代码的时候

改完问一句：**这次改动让哪句话变错了？** 有就在**同一个提交里**改。

没有就在提交信息里写一行「文档：无」—— 写下来才说明真的想过。

这条不是形式主义。攒着做，你查的是「我当时记得改过什么」；同提交做，你查的是「这次改动让什么变错了」。后者只有刚改完那几分钟看得出来 —— 本项目错过一次：界面上的「官方依据」被删了十个提交之后，`README` 还写着它。

## 不在这里的东西

- **`README.md`（根）** —— 使用者文档：装、启、排错。它是 GitHub 的落地页，不挪进 `docs/`。
- **代码注释** —— 局部契约：行为、失败、时序、所有权。属于它守着的那个文件。
- **提交信息** —— 历史、走查、一次性的取舍记录。
- **`tests/`** —— 测试和它们的夹具。**实测出来的容器行为**已经挪到 `design/container-findings.md`。
